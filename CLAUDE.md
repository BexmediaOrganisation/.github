# Bexmedia standards for AI coding tools

You are working in a BexmediaOrganisation repo. Bexmedia's SOPs on monday.com are the single source of truth for how work is done. Read the SOP that applies before you act, and follow it exactly. If anything here or in a repo's own CLAUDE.md disagrees with an SOP, the SOP wins.

## Which SOP applies

| When you are… | Read |
|---|---|
| Taking an idea all the way to a release (the usual order of work) | From idea to release: https://bexmediastudio.monday.com/docs/18439308736 |
| Starting a new repo | Starting a new repo: https://bexmediastudio.monday.com/docs/18439133662 |
| Creating a branch, committing, opening or merging a pull request | Commits and pull requests: https://bexmediastudio.monday.com/docs/18438793528 |
| Releasing a version, tagging, changing version numbers or changelogs | Versioning and releases: https://bexmediastudio.monday.com/docs/18438794583 |
| Building or changing a tool with Claude Code (the skills workflow) | Building with AI: https://bexmediastudio.monday.com/docs/18439287632 |
| Adding a tool to the Bexmedia App Store, or changing its listing or icon | Adding an app to the Bexmedia App Store: https://bexmediastudio.monday.com/docs/18439313835 |
| Writing or changing a GitHub Actions workflow, or choosing `runs-on` | GitHub self-hosted runners: https://bexmediastudio.monday.com/docs/18438628008 |

## How to read the SOPs

Use the monday.com connector, if you have it, to read the doc at the link above. Each link ends in the doc's ID.

If you cannot read monday.com, stop and ask the person you are working with to paste the SOP, rather than guessing.
